# Bosch LPR to CUSTronics LED Middleware
## Developer Setup, Installation & Maintenance Guide

## 1. Project overview

This project connects a Bosch camera with IVA Pro License Plate Recognition to a CUSTronics LED display through MQTT and a Python middleware application.

The middleware receives plate metadata, processes the plate number, identifies the IN/OUT direction, and routes the event to the corresponding LED controller.

### System architecture

```text
Bosch LPR Camera
       |
       | MQTT metadata / JSON
       v
MQTT Broker (Mosquitto)
192.168.0.100:1883 // current testing = 127.0.0.1
       |
       | parking/bosch/IN
       | parking/bosch/OUT
       v
Python Middleware
       |
       +--> Parse plate number
       +--> Validate / detect duplicates
       +--> Identify IN or OUT
       |
       v
Event Queue
       |
       +------------------+
       |                  |
       v                  v
    IN LED              OUT LED
    Controller          Controller
       |                  |
       v                  v
 Virtual display / future physical RS485 output
```

### Current implementation status

- MQTT reception and plate parsing have been tested with simulated messages.
- The virtual LED display is available for software testing.
- Physical CUSTronics RS485 output is not verified. The vendor's command protocol must be obtained and implemented first.
- Physical barrier relay operation is not verified. Authorization rules, wiring, and safety behaviour must be confirmed before hardware testing.

## 6. Install and verify Mosquitto

Mosquitto is the MQTT broker used in the reference configuration.

If Mosquitto is already installed on the machine, verify the installation rather than installing it again.

The reference executable path is:

```text
C:\Program Files\Mosquitto\
```

Check whether the executable exists:

```powershell
Test-Path "C:\Program Files\Mosquitto\mosquitto_pub.exe"
Test-Path "C:\Program Files\Mosquitto\mosquitto_sub.exe"
```

Check whether port 1883 is listening:

```powershell
Get-NetTCPConnection -LocalPort 1883 -State Listen
```

If no listener appears, check whether the Mosquitto service is running and whether its configuration is correct.

### Network configuration

The reference broker address is:

```text
192.168.0.100:1883
```

The broker must be reachable from the middleware PC and the Bosch camera.

If the camera and broker are on separate devices, verify that:

- Both devices have compatible IP addresses and subnet settings.
- The broker listens on the required network interface.
- Windows Firewall permits the required MQTT traffic.
- The camera is configured with the correct broker IP, port, and topic names.

Do not assume the reference IP address is correct for every development environment.

## 9. Test MQTT without the physical camera

Use simulated MQTT messages to verify the software path before connecting real camera events.

### Open a second PowerShell terminal

Keep `main.py` running in the first terminal.

net start mosquitto (run cmd as admin)

//run in second cmd
"C:\Program Files\Mosquitto\mosquitto_sub.exe" -h 127.0.0.1 -p 1883 -t "parking/bosch/#" -v

### Test an IN event

```powershell
& "C:\Program Files\Mosquitto\mosquitto_pub.exe" `
  -h 192.168.0.100 -p 1883 `
  -t "parking/bosch/IN" `
  -m '{"Data":{"LicensePlateInfo":{"LicensePlateInfo":{"PlateNumber":{"#text":"PUTRAJAYA1234"}}}}}'
```

### Test an OUT event

```powershell
& "C:\Program Files\Mosquitto\mosquitto_pub.exe" `
  -h 192.168.0.100 -p 1883 `
  -t "parking/bosch/OUT" `
  -m '{"Data":{"LicensePlateInfo":{"LicensePlateInfo":{"PlateNumber":{"#text":"PUTRAJAYA1234"}}}}}'
```

Replace `192.168.0.100` with the actual broker address if needed.

These commands simulate an MQTT event. They do not prove that the Bosch camera is publishing real license-plate metadata.

### Expected software behaviour

| Test | Expected result |
|---|---|
| Publish IN event | IN event is received and parsed |
| IN event passes validation | Routed to the IN controller |
| Publish OUT event | OUT event is received and parsed |
| OUT event passes validation | Routed to the OUT controller |
| Virtual LED enabled | Corresponding virtual display updates |
| Invalid JSON | Error is logged without crashing the application |
| Missing plate field | Event is rejected or ignored safely |

If the event does not appear, check the broker address, topic, subscription, and application logs.

## 10. Test plate text and spaces

Use this payload to test a plate-like string containing an internal space:

```powershell
& "C:\Program Files\Mosquitto\mosquitto_pub.exe" `
  -h 192.168.0.100 -p 1883 `
  -t "parking/bosch/IN" `
  -m '{"Data":{"LicensePlateInfo":{"LicensePlateInfo":{"PlateNumber":{"#text":"QOE INTELLIGENCE"}}}}}'
```

Check the logs at each stage:

1. MQTT payload extraction
2. Processor normalization
3. Event queue insertion
4. LED display validation
5. Virtual scrolling/display output

If the space disappears, inspect `PlateProcessor.clean_plate()` in `processor.py`. A regular expression that allows only letters and digits will remove spaces.

To preserve internal spaces for display testing:

```python
@staticmethod
def clean_plate(plate):
    if not isinstance(plate, str):
        return ""

    return re.sub(r"[^A-Z0-9 ]", "", plate.upper()).strip()
```

Confirm that `re` is imported in the module. Consider the project's real license-plate matching rules separately from arbitrary text display tests.

## 11. Connect and configure the Bosch camera

Only proceed after the broker and middleware work with simulated MQTT events.

1. Confirm the camera is powered on and reachable.
2. Sign in to the Bosch camera web interface.
3. Confirm that the IVA Pro License Plate feature is licensed and configured.
4. Configure the camera's MQTT broker connection to point to the correct broker IP and port.
5. Configure the MQTT topic prefix or event topics to match the middleware subscriptions.
6. Enable the relevant LPR/metadata events for publication.
7. Trigger a controlled plate-recognition test.
8. Inspect the actual MQTT topic and JSON payload.
9. Compare the real payload with the parser in `cameras/bosch_mqtt.py`.
10. Update the parser only if the actual camera payload differs from the expected structure.

The exact camera menu names depend on firmware and configuration. Do not assume that every Bosch camera exposes the same MQTT settings.

A real camera event may contain metadata unrelated to license-plate recognition. Confirm that the payload actually contains a plate before changing the parser.

## 12. LED display and serial-port setup

The reference configuration uses:

- IN display: `COM60`
- OUT display: `COM61`
- Serial settings: `9600, 8N1`

These are example configuration values. Check the actual hardware and Device Manager before using them.

List currently detected serial ports:

```powershell
[System.IO.Ports.SerialPort]::GetPortNames()
```

If a port is missing, check the USB adapter, Device Manager, assigned COM number, and whether another application has opened the port.

### Virtual versus physical output

**Virtual mode:** Used to test event routing, text, row layout, scrolling, and clearing.

**Physical mode:** Requires a confirmed CUSTronics RS485 protocol, including command framing, addressing, row/colour commands, encoding, and any required checksum or acknowledgement.

Do not enable physical serial writes merely because the virtual display works or a COM port is detected.

---

## 13. Barrier integration

Barrier operation is a separate feature and should remain disabled or simulated until fully verified.

Before physical testing, confirm:

- The authorization source and decision rules
- Which plates are allowed to open the barrier
- The relay interface and electrical requirements
- The correct barrier input terminals
- Pulse duration and trigger behaviour
- Safety inputs and fail-safe behaviour
- The physical wiring and installation procedure

A recognized plate is not automatically authorized. A log reporting a simulated relay action does not prove the physical barrier has opened.

## 14. Troubleshooting guide

| Problem | What to check first |
|---|---|
| `python` command unavailable | Python installation and PATH |
| Dependency import error | Virtual environment and dependency file |
| `main.py` fails to start | First traceback error and configuration |
| MQTT connection fails | Broker service, IP, port, firewall, network |
| No events received | Topic names and subscriptions |
| Event received without a plate | Actual JSON payload and parser |
| IN/OUT direction is wrong | Topic mapping and event routing |
| Plate spaces disappear | Plate normalization and downstream text handling |
| Text is cut off | Eight-character row limit and scrolling |
| Virtual LED does not update | Queue format, consumer, controller initialization |
| COM port unavailable | Device Manager and current port assignments |
| Physical LED does not display | RS485 protocol and hardware configuration |
| Barrier does not open | Authorization mapping, relay mode, wiring, safety checks |
